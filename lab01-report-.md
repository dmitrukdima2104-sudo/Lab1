### 1. Список таблиць бази даних
Спочатку перевіримо, які таблиці є в нашій базі даних:
```sql
SELECT
    table_name
FROM information_schema.tables
WHERE
    table_schema = 'public'
ORDER BY
    table_name;
```

order_items, orders, product_sales_summary, products, regions, suppliers.

### 2. Базові запити, фільтрація та сортування (Рівень 1)
У цьому блоці ми робимо прості вибірки, сортування та обмежуємо кількість рядків.

```sql
-- Отримати всіх клієнтів
SELECT
    *
FROM customers;

-- Вивести назви товарів і їхні ціни
SELECT
    product_name,
    unit_price
FROM products;

-- Фільтрація співробітників за посадою (відділ продажів)
SELECT
    *
FROM employees
WHERE
    title ILIKE '%продаж%';

-- Замовлення зі статусом delivered
SELECT
    *
FROM orders
WHERE
    order_status = 'delivered';

-- Сортування товарів за зростанням ціни та обмеження ліміту (топ-10 найдорожчих)
SELECT
    *
FROM products
ORDER BY
    unit_price DESC
LIMIT 10;
```

Результат: Отримано 15 записів клієнтів, включаючи як фізичних осіб, так і юридичні особи з різних міст України.

Скріншот![Базові запити](screenshots/sql%20skrin%20krok2.png)

### 3. Пошук за зразком (LIKE / ILIKE)
Використовується для пошуку підрядків (наприклад, за частиною імені чи назви товару).

```SQL
-- Клієнти, чиї імена починаються на "Іван"
SELECT
    *
FROM customers
WHERE
    contact_name LIKE 'Іван%';

-- Товари, в назві яких є слово "phone" або "телефон"
SELECT
    *
FROM products
WHERE
    product_name ILIKE '%phone%'
    OR product_name ILIKE '%телефон%';

-- Самостійні приклади:
SELECT
    *
FROM customers
WHERE
    email LIKE '%@gmail.com';

SELECT
    *
FROM products
WHERE
    product_name ILIKE '%чохол%';

SELECT
    *
FROM employees
WHERE
    last_name LIKE '%ук';
```
Скріншот результату:![Пошук LIKE](screenshots/sql%20skrin%20krok3.png)

### 4. Логічні оператори (AND, OR, NOT)
Дозволяють комбінувати кілька умов одночасно.

```SQL
-- Товари у ціновому діапазоні від 15000 до 50000 грн
SELECT
    *
FROM products
WHERE
    unit_price > 15000
    AND unit_price < 50000;

-- Активні товари (є на складі і не зняті з виробництва)
SELECT
    *
FROM products
WHERE
    units_in_stock > 0
    AND NOT discontinued;

-- Клієнти не з Києва, у яких вказано номер телефону
SELECT
    *
FROM customers
WHERE
    NOT city = 'Київ'
    AND phone IS NOT NULL;
```
Скріншот результату:![Логічні оператори](screenshots/sql%20skrin%20krok4.png)

### 5. Оператори IN, BETWEEN, IS NULL
Спеціальні оператори для перевірки списків, інтервалів дат/цін та пустих полів (NULL).

```SQL
-- Клієнти з міст Київ, Харків, Одеса, Дніпро (оператор IN)
SELECT
    *
FROM customers
WHERE
    city IN ('Київ', 'Харків', 'Одеса', 'Дніпро');

-- Замовлення за перший квартал 2024 року (оператор BETWEEN)
SELECT
    *
FROM orders
WHERE
    order_date BETWEEN '2024-01-01' AND '2024-03-31';

-- Клієнти без вказаної компанії — фізичні особи (оператор IS NULL)
SELECT
    *
FROM customers
WHERE
    company_name IS NULL;
```
Скріншот результату:![Оператори IN BETWEEN](screenshots/sql%20skrin%20krok5.png)

### 6. Складне сортування та пагінація (OFFSET / LIMIT)
Використовується для сортування за кількома колонкам та поділу великої кількості даних на сторінки.

```SQL
-- Складне сортування за категорією (зростання) та ціною (спадання)
SELECT
    *
FROM products
ORDER BY
    category_id ASC,
    unit_price DESC;

-- Пагінація: виведення другої сторінки товарів (по 10 штук на сторінку, пропускаємо перші 10)
SELECT
    *
FROM products
ORDER BY
    product_name
LIMIT 10 OFFSET 10;
```

# Контрольні запитання
## 1. Що таке SQL і для чого він призначений? Поясніть різницю між декларативною та імперативною мовами програмування на прикладі SQL.
Відповідь: SQL (Structured Query Language) — це стандартизована мова програмування, призначена для створення, модифікації та керування даними в реляційних базах даних.
Різниця:
Імперативні мови (наприклад, C++, Python) вимагають розписати як саме виконати завдання покроково (зроби цикл, перевір умовою, візьми елемент).
Декларативний SQL вимагає описати лише що саме потрібно отримати («дай мені клієнтів з Києва»), а СУБД сама вирішує, яким найефективнішим шляхом виконати цей запит.

## 2. Опишіть порядок виконання частин SELECT запиту. Чому важливо розуміти цю послідовність при написанні складних запитів?
Порядок виконання запиту в СУБД відрізняється від порядку його написання:
  1 FROM (визначається джерело даних / таблиця)
  2 WHERE (фільтруються рядки)
  3 SELECT (вибираються потрібні стовпці та обчислюються поля)
  4 ORDER BY (сортуються результати)
  5 LIMIT / OFFSET (обмежується кількість виведених рядків)
Чому це важливо: Розуміння цього рятує від помилок (наприклад, ти не можеш посилатися в WHERE на псевдонім, створений у SELECT, бо SELECT виконується пізніше)

## 3. У чому різниця між операторами = та LIKE? Наведіть приклади, коли доцільно використовувати кожен з них.
= — це оператор точного збігу. Використовується, коли значення має збігатися на 100% (наприклад, WHERE status = 'delivered' або WHERE id = 5).
LIKE — це оператор пошуку за шаблоном за допомогою спецсимволів % та _. Використовується для неточного пошуку (наприклад, знайти всіх, у кого прізвище починається на «Петр...» — WHERE last_name LIKE 'Петр%').

## 4. Поясніть призначення wildcards % та _ в операторі LIKE. Чи можна їх комбінувати в одному шаблоні?
% — замінює будь-яку кількість символів (включно з їх повною відсутністю).
_ — замінює рівно один будь-який символ.
Так, їх можна комбінувати в одному шаблоні (наприклад, LIKE '_і%' — другий і третій символи «і», а далі будь-що).

## 5. Чому оператор WHERE company_name = NULL не працює для пошуку записів з відсутніми значеннями? Як правильно працювати з NULL значеннями в SQL?
NULL у базі даних означає «невідоме» або «відсутнє» значення. 
Будь-яке математичне чи логічне порівняння з NULL через = дає неозначений результат (NULL), а не true чи false.
Як правильно: Використовувати спеціальні оператори IS NULL або IS NOT NULL (наприклад, WHERE company_name IS NULL).

## 6. Поясніть різницю між логічними операторами AND та OR. Як впливає пріоритет операторів на результат запиту A OR B AND C?
AND (І) вимагає виконання всіх умов одночасно.
OR (АБО) вимагає виконання хоча б однієї з умов.
Пріоритет: AND має вищий пріоритет, ніж OR. Вираз A OR B AND C інтерпретується як A OR (B AND C). Якщо забути про дужки, результат може вийти зовсім не таким, як планувалося.

## 7. У яких випадках оператор BETWEEN включає граничні значення, а в яких — ні? Як написати умову для виключення границь діапазону?
BETWEEN у SQL завжди включає граничні значення (включно з межами).
Щоб виключити межі, потрібно замінити його на оператори суворої нерівності: WHERE column > 10000 AND column < 50000

## 8. Для чого використовується LIMIT та OFFSET? Напишіть формулу для розрахунку OFFSET при пагінації, якщо відома сторінка та розмір сторінки
LIMIT обмежує максимальну кількість рядків у результаті, а OFFSET пропускає задану кількість рядків (використовується для розбиття на сторінки — пагінації).
Формула OFFSET: OFFSET=(номер_сторінки−1)×розмір_сторінки

## 9. Чому важливо використовувати ORDER BY разом з LIMIT? Що може статися, якщо не вказати сортування при обмеженні кількості записів?
Без ORDER BY база даних може повернути рядки в будь-якому довільному порядку (який залежить від внутрішнього стану сховища на момент запиту). Порядок не буде гарантованим, і при кожному запуску запиту з LIMIT ти можеш отримувати різні набори даних.

## 10. Поясніть різницю між LIKE та ILIKE в PostgreSQL. В яких ситуаціях кожен з них буде більш доцільним?
LIKE — чутливий до регістру (чутливий до великих/маленьких літер: 'Іван' і 'іван' для нього різні речі).
ILIKE — нечутливий до регістру (специфічне розширення PostgreSQL, яке ігнорує регістр символів).
Доцільність: ILIKE зручно використовувати для пошуку імен чи міст, коли користувач міг ввести літери у різному регістрі.

## 11. Як PostgreSQL обробляє NULL значення при сортуванні за замовчуванням? Як це можна змінити за допомогою NULLS FIRST/LAST
За замовчуванням у PostgreSQL NULL вважаються «найбільшими» значеннями серед усіх, тому при сортуванні ASC вони описуються в самому кінці списку.
Змінити це можна за допомогою модифікаторів NULLS FIRST (ставити пусті значення на початок) або NULLS LAST (примусово в кінець).

## 12. Наведіть приклад бізнес-сценарію, де потрібно використати складну комбінацію умов з дужками. Поясніть, як неправильне групування логічних операторів може призвести до некоректних результатів.
Сценарій: Знайти всіх клієнтів із Києва або Львова, які обов'язково є юридичними особами (customer_type = 'company').
Правильний запит: WHERE (city = 'Київ' OR city = 'Львів') AND customer_type = 'company'.
Якщо забути дужки (WHERE city = 'Київ' OR city = 'Львів' AND customer_type = 'company'), через пріоритет AND база спочатку знайде львівські компанії, а потім додасть усіх підряд мешканців Києва (навіть фізосіб), що повністю зламає логіку бізнес-вибірки.
